The complete experimental process
Integrating and Evaluating a Fruit Fly Connectome Model for Visual Steering in a Driving Simulator
Yechuan Wei · 2026

The initial question: a useful directional response
The project started with low-speed simulated driving. The first question was smaller than full road following: could visual stimulation of an existing fly connectome model produce a measurable and repeatable directional response, and could that output then steer DonkeyCar? The upstream system already supplied a graph, sensory encoders, and action rules. I tested these parts separately so I could tell what the neural model did from what the upstream code's built-in fallback rules did. Unstable early responses led to tests of camera interfaces, learned readouts and internal parameters, followed by continuous driving and recovery evaluation. The timeline records each change of objective.

The upstream model and the added driving system
The starting point was a pinned version of fly-brain-minecraft. It supplied a MaleCNS-derived graph, cell identities and positions, a visual encoder, a spiking core, and a motor decoder. The retained graph has 176,422 nodes and 6,287,749 aggregated connections. It keeps neuron pairs with at least five synapses. I first separated this core from the Minecraft body and its fallback actions, then added headless probes and records. The camera and driving loop came later.

The first stimulus and output tests
The first model accumulated input and emitted spikes at a threshold. I compared silence, a known sugar pathway, brightness patterns, moving targets, and directly supplied visual features. I also removed or reversed the stimulus. Some feature inputs produced responses, while brightness alone gave weak steering responses. Activity could remain after the stimulus ended. The next step was an observable vehicle loop, followed by separate tests of visual input and learned output. The records do not give one common cause for every early zero response.

A continuous core with trainable connections
The fixed spiking core and its numerical output interface did not provide the internal gradient path needed here. C1 first explored a few global parameters. C2 then introduced continuous recurrent computation and a trainable gain on each existing connection. In the final controller, a gain can scale its signed normalized base weight from 0.25 to 1.75. The graph and connection signs stay fixed. Learning can now update allowed parameters from recorded experience. Driving quality still has to be measured in fixed-weight evaluation.

From an eight-by-eight image to 817 spatial samples
The assisted model compressed each image to 64 brightness values in an eight-by-eight grid, alongside four route or vehicle hints. A learned dense map with bias transformed all 68 values to 3,324 R1 to R6 inputs through tanh. C8 used this mapping with fixed-weight weights. C10 replaced that image path. It converted the original 160-by-120 image to grayscale and sampled at directions associated with the model eye columns. Of 1,769 directions, 817 fell inside the camera's field of view. Each brightness value is a continuous number from zero to one. Centering, gain, bias, and tanh turn it into bounded input. Cells outside the view remain in the graph and receive no direct camera drive.

Why L1 and L2 became the visual input
L1 and L2 cover all 817 visible sampling positions in the column annotations. The upstream inferred positions for R1 to R6 photoreceptors cover only 216 of them. L1 and L2 therefore gave the more complete engineering input map. There are 1,634 directly stimulated cells, with 817 of each type. Most samples go to one L1 and one L2 on the same side and column. Two annotation exceptions give one target at a left sample and three at a right sample. The display preserves those actual assignments.

Paired signal and no-input recurrent states
The final core uses signed continuous activity. Each internal update combines connected activity, bias, and current input, applies tanh, and mixes the result with the previous state. It repeats this calculation four times on the same image. The resulting numbers carry into the next driving decision. This is the recurrent state. Biases also produce activity without external input, so a second state receives no external drive. Both states share parameters and reset together. The readout compares their activity at the same moment.

Descending neurons and the steering readout
Descending neurons carry signals from the brain toward the ventral nerve cord, so the readout uses all 1,314 DNs in the graph. It subtracts the reference state, applies layer normalization, and passes the features through 64 hidden units to produce a steering distribution. Training samples from that distribution. Evaluation uses tanh of its mean. Steering ranges from minus one to plus one. Later scored driving learns steering only and sends a fixed throttle of 0.03. The replay colours show saved normalized DN features.

Collecting experience and updating with PPO
The collector stores the input used for a decision, the action, its probability under the collecting policy, the value estimate, and the reward and timing that follow. The learner reuses that batch while limiting how quickly the policy moves away from the collecting policy. This is the project implementation of proximal policy optimization, or PPO. Reward versions combine progress, offset, heading, and action changes. The timeline records those revisions. In camera-only operation, geometry supports rewards, reset placement, and scoring, rather than route hints to the policy.

What a checkpoint preserves
A checkpoint is a traceable saved state. It can include network and readout parameters, Adam accumulators, and update counters. Continuation checks the hash, saved stage, and restored parameter groups, rather than the filename alone. Both final feedback conditions restore the same R23 checkpoint and saved Adam optimizer state, then begin new driving episodes with fresh recurrent histories. The lineage follows those actual restore records. A higher run number does not mean that it continued from the previous run's weights.

Rebuilding recurrent history before a short update
After connection gains change, the old input history produces a different recurrent state. Before learning from a short sequence, the program replays saved brightness numbers with the current parameters and rebuilds both states. It computes the earlier prefix without gradients, then keeps gradients through the selected 16 decisions. This is truncated backpropagation through time, or TBPTT. The final gradient routing also separates the value prediction error from the policy update. Value loss trains only the value output. Policy and entropy terms train the shared readout and allowed core parameters.

Verified starts and accepted action intervals
Before scoring, the simulator reset the car, applied the brakes and checked the road and starting pose. Later comparisons used the saved road geometry and measured starts. Camera time, decision time and action-end time were recorded separately. A step that failed the timing or command-echo check stayed out of learning. The valid earlier steps and the rejected messages were kept. In fixed-weight tests, a failed attempt was kept and the whole case could be repeated after a verified reset.

Parallel simulators and one shared learner
I first ran complete model-and-simulator copies side by side. A 64-worker test partly failed; a revised 32-worker setup completed. Later, several cars shared one learner. The final setup used one L40 GPU, 32 CPU cores and 187,950 MiB of host memory for 24 training simulators, four development evaluators and four held-out evaluators. Each car kept its own recurrent state and input history. Evaluation data stayed out of learning. Roihu's x86 L40 nodes could run the Linux simulator and provide the compute for the large graph, paired states, four calculation rounds and repeated history reconstruction.

The final matched movement-feedback comparison
Similar images can occur while the car is turning in different ways. The final experiment mapped the previous accepted steering command, speed, and estimated yaw rate to 3,324 R1 to R6 cells. This new linear projection has 9,972 weights and passes through tanh before entering the recurrent core. Movement and zero conditions have the same structure, but the zero condition sets all three inputs to zero. Both new maps start at zero. The movement map becomes nonzero, while the zero map stays zero. Existing connection gains, readout, and exploration scale continue learning in both conditions. R38 completed both budgets and evaluations, with no clear overall improvement.

Full account

Engineering check or repair

Silence produced no spikes, while the known sugar pathway produced activity. This gave the later visual tests a working reference.

Full account

003. A bright spot reaches the visual input, but produces no turn
Scientific attempt

The first visual question was simple: could a bright spot on a dark background produce a directional readout? This was the closest test of the original light-stimulus idea. Each sequence started a fresh network. Within a sequence, state continued through baseline, center, one side, center, the opposite side, and withdrawal. A mirrored sequence reversed the order, and every phase lasted 500 milliseconds. I did not inject a desired action into the output cells, and I did not train parameters. The records showed that retinal and early visual populations received input. However, both raw yaw and decoded yaw remained zero in every recorded window. The next choice was therefore to test a moving stimulus, before changing gains or the output mapping.


004. Motion alone still does not activate the turning readout
Scientific attempt

After the static spot produced no turn, I tried a moving dark target on a bright background. The neural core, readout, and internal parameters stayed fixed. The upstream object-feature channels remain disabled. I changed motion first because it addresses a concrete possibility: perhaps the static trial did not supply the visual changes this interface needed. Both mirrored sequences still produce zero turning readout, although early visual input was engaged. I kept that negative result. The next test enabled an existing higher-level object-feature input as a separate condition. This allowed me to ask whether the level of sensory entry matters, while keeping retinal stimulation and analytic features clearly distinguished.


005. A higher-level input produces activity, but not reliable left–right control
Scientific attempt

I read selected descending neurons as candidate motor-related outputs. Enabling the object-feature channels finally produced nonzero descending activity and turning output. The question immediately became whether the response reliably distinguishes left from right. In the normal sequence, the raw-yaw tail means were −0.52 for the left target, −0.64 for the later right target, and −0.62 after withdrawal. The mirrored sequence gave +0.14, +0.06, and zero. These sequences differ in both central motion and internal history. In one condition, left DNa02 activity also remained after the target disappears, so decoder smoothing was not the whole explanation. The input could influence the model, but it did not yet provide reliable bidirectional control. I next tested each side from a fresh network, reducing the carryover from earlier phases.

010. The self-rotation input reaches the correct side, but leaves a biased state
Scientific attempt

This condition uses the upstream analytic HS self-rotation input. It was neither a camera image nor rendered optical flow. With uniform brightness and no objects, I supplied +300 or −300 source degrees per second. Three seeds received both signs. Positive input activates left HS, and negative input activates right HS, so the intended input side was engaged. The turning response was still asymmetric. 015. Wheel centering does not restore the earlier heading
Engineering check or repair

Full account

Across 144 telemetry packets, the signed phases change reported yaw by approximately −2.607 and +4.498. 016. An opposite input does not reliably reverse the readout
Scientific attempt

017. Weaker input quiets the tail, but does not solve directional control
Scientific attempt

I reduced the input from ±300 to ±150 source degrees per second, keeping the seeds, orders, core, and decoder unchanged. The upstream nonlinear formula changed the prescribed HS generator rate from 100 to about 66.7 hertz; it did not simply halve it.
